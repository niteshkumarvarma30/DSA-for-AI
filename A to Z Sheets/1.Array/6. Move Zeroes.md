# Move Zeroes

## Concepts & Explanation
The goal of this problem is to move all `0`s to the end of an array while maintaining the relative order of the non-zero elements. This operation must be done in-place.

The provided code showcases two approaches:

### 1. Using an Extra List (Brute Force)
- **Concept**: We can iterate over the original array and separate the non-zero elements from the zeroes. We append all non-zero elements into a new temporary list `not_zero`, and keep a count `cnt` of how many zeroes we encounter. Once all non-zero elements are collected, we append `cnt` number of zeroes to the end of `not_zero`. Finally, we copy the elements back to the original array.
- **Implementation**: After creating the new array, Python's slice assignment `nums[:] = not_zero[:len(nums)]` efficiently replaces the original array's elements with our newly constructed ones.
- **Time Complexity**: $O(N)$ because we traverse the array to extract elements, and then traverse again to append zeroes and assign them back.
- **Space Complexity**: $O(N)$ because we allocate a temporary list `not_zero` proportional to the size of the original array.

### 2. Using Writer and Reader Pointers (Optimal / In-place)
- **Concept**: To achieve $O(1)$ space, we can use a two-pointer approach (often called reader and writer pointers or fast and slow pointers). 
  - The reader pointer (`r`) traverses the array to look for non-zero elements.
  - The writer pointer (`l`) keeps track of the position where the next non-zero element should be placed.
- **Implementation**:
  - We initialize the writer pointer `l = 0`.
  - The reader pointer `r` loops through every index of the array.
  - Whenever `nums[r]` is not `0`, we swap the elements at `l` and `r` (`nums[l], nums[r] = nums[r], nums[l]`).
  - After swapping, we increment the writer pointer `l`. 
  - By doing this, we systematically push all non-zero elements to the front. The zeroes are naturally left behind or swapped to the end of the array.
- **Time Complexity**: $O(N)$ because we iterate through the array exactly once.
- **Space Complexity**: $O(1)$ because the modifications are done entirely in-place without creating any extra arrays.
