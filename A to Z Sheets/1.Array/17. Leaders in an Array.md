# Leaders in an Array

**Difficulty:** Easy / Medium  
**Topics:** Array

## Problem Description
Given an integer array `nums`, return a list of all the leaders in the array.

A **leader** in an array is an element whose value is strictly greater than all elements to its right in the given array. The rightmost element is always a leader. The elements in the leader array must appear in the order they appear in the `nums` array.

### Examples

**Example 1:**
- **Input:** `nums = [1, 2, 5, 3, 1, 2]`
- **Output:** `[5, 3, 2]`
- **Explanation:** `2` is the rightmost element, `3` is the largest element in the index range `[3, 5]`, `5` is the largest element in the index range `[2, 5]`.

**Example 2:**
- **Input:** `nums = [-3, 4, 5, 1, -4, -5]`
- **Output:** `[5, 1, -4, -5]`
- **Explanation:** `-5` is the rightmost element, `-4` is the largest element in the index range `[4, 5]`, `1` is the largest element in the index range `[3, 5]` and `5` is the largest element in the range `[2, 5]`.

---

## Concepts & Explanation: The Problem
A "leader" is defined as any element that is strictly greater than all the elements to its right.
Let's look at an example array: `[16, 17, 4, 3, 5, 2]`.

If we use a **brute-force approach**, we would stand at `16` and scan the entire rest of the array (`17, 4, 3, 5, 2`) to see if anything is bigger. Then we would move to `17` and scan everything to its right, and so on. This nested looping causes a slow $\mathcal{O}(N^2)$ time complexity.

### The Intuition: Read from Right to Left
Instead of looking left-to-right and repeatedly scanning the future, what if we just read the array backwards?
When you scan from right-to-left, you can keep a running track of the maximum element you have seen so far.

Let's do a dry run on `[16, 17, 4, 3, 5, 2]`.
- **Initialize:** Set `current_max = -infinity`. Our result array is empty `[]`.

1. **Look at `2` (the last element):**
   - Is `2 > current_max` (`-inf`)? Yes!
   - *Intuition:* Because there is nothing to the right of the last element, the last element is always a leader.
   - Add `2` to result.
   - Update `current_max = 2`.

2. **Look at `5`:**
   - Is `5 > current_max` (`2`)? Yes!
   - *Intuition:* If `5` is bigger than the biggest thing we've seen on the right, it must be bigger than everything on the right! It's a leader.
   - Add `5` to result.
   - Update `current_max = 5`.

3. **Look at `3`:**
   - Is `3 > current_max` (`5`)? No.
   - *Intuition:* The number `3` is hiding behind the taller number `5`. It is not a leader.
   - `current_max` stays `5`.

4. **Look at `4`:**
   - Is `4 > current_max` (`5`)? No.

5. **Look at `17`:**
   - Is `17 > current_max` (`5`)? Yes!
   - Add `17` to result.
   - Update `current_max = 17`.

6. **Look at `16`:**
   - Is `16 > current_max` (`17`)? No.

### The Final Step
Because we built our list by scanning backwards, our result array currently looks like this: `[2, 5, 17]`.
Most problems will ask for the leaders in their original left-to-right order. So, the very last step is to just **reverse** the result array to `[17, 5, 2]`!

---

## Code
```python
class Solution:
    def leaders(self, nums):
        n = len(nums)
        leader = float('-inf')
        res = []
        
        # Traverse the array from right to left
        for i in range(n - 1, -1, -1):
            # If the current element is greater than or equal to the maximum seen so far
            if nums[i] >= leader:
                res.append(nums[i])
                leader = nums[i]
                
        # Reverse the result to maintain the original left-to-right order
        res.reverse()
        return res    
```
