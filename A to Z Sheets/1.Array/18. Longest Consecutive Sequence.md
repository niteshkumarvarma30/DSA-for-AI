# Longest Consecutive Sequence

**Difficulty:** Medium  
**Topics:** Array, Hash Table

## Problem Description
Given an unsorted array of integers `nums`, return the length of the longest consecutive elements sequence.
You must write an algorithm that runs in $O(n)$ time.

---

## Concepts & Explanation: Three Approaches

We can solve this problem in three different ways, ranging from brute force to the optimal approach.

### 1. Brute Force Approach
- **Intuition**: The most basic way is to pick every single element in the array and see how long of a sequence we can build from it. For a number `x`, we check if `x+1` exists in the array, then `x+2`, and so on.
- **Approach**: Iterate through the array. For each number, start a `while` loop that continuously checks if the next consecutive number (`num + 1`) is present in the `nums` array. We keep a running count of the maximum sequence found.
- **Time Complexity**: $O(N^2)$ or $O(N^3)$. Because looking up `num + 1` in an unsorted list takes $O(N)$ time, doing this inside a `while` loop which is inside a `for` loop makes it extremely slow for large inputs.
- **Space Complexity**: $O(1)$.

### 2. Better Approach (Sorting)
- **Intuition**: If we sort the array, all consecutive numbers will end up right next to each other. We can then just walk through the array once and count the sequences.
- **Approach**: First, we sort the `nums` array. We maintain a `last_smaller` variable to track the previous number in a valid sequence, and a `count` for the current sequence length.
  - If the current number is exactly `last_smaller + 1`, the sequence continues (`count += 1`).
  - If the current number is equal to `last_smaller`, it's a duplicate. We do nothing and move to the next element.
  - If the current number is anything else, the sequence breaks. We reset our `count = 1`.
  - We constantly update the `longest` sequence recorded so far.
- **Time Complexity**: $O(N \log N)$ because sorting the array takes $N \log N$ time. The subsequent iteration takes $O(N)$ time.
- **Space Complexity**: $O(1)$ (or $O(N)$ depending on the sorting algorithm used under the hood).

### 3. Optimal Approach (Hash Set)
- **Intuition**: The bottleneck in the brute-force approach is searching for `num + 1` in an array, which takes $O(N)$. If we throw everything into a Hash Set first, searching becomes $O(1)$! Furthermore, we only need to start counting a sequence if it's the *true beginning* of a sequence. If `num - 1` exists in the set, then `num` is just the middle of some sequence, and we don't need to do redundant work starting from it.
- **Approach**: 
  - Convert the array into a Hash Set.
  - Iterate through the set. For each number `num`, check if `num - 1` exists in the set.
  - If `num - 1` **is not** in the set, it means `num` is the very first number of a consecutive sequence.
  - From this starting point, keep checking for `num + 1`, `num + 2`, etc., in the set, incrementing your count.
- **Time Complexity**: $O(N)$. Creating the set takes $O(N)$. We then iterate through the set, and the inner `while` loop only runs for the exact length of the sequences. Across the entire program, the `while` loop will execute at most $N$ times total. So it's $O(N) + O(N) = O(N)$.
- **Space Complexity**: $O(N)$ to store elements in the Hash Set.

class Solution(object):
    def longestConsecutive(self, nums):
        """
        :type nums: List[int]
        :rtype: int
        """
        
        # --- 1. Optimal Approach (Hash Set) ---
        my_set = set()
        for i in range(len(nums)):
            my_set.add(nums[i])
            
        longest = 0
        for num in my_set:
            # Check if this number is the START of a sequence
            if num - 1 not in my_set:
                x = num
                count = 1
                # Keep finding consecutive numbers
                while x + 1 in my_set:
                    count += 1
                    x += 1
                longest = max(longest, count)
                
        return longest
