# Rotate Array

## Concepts & Explanation
The problem requires us to rotate an array to the right by `k` steps in-place. Before applying any rotation logic, we always compute `k = k % n` (where `n` is the length of the array) because rotating an array by its length `n` results in the original array. This handles cases where `k` is larger than the array length.

The provided code demonstrates three different approaches:

### 1. Using Pop and Insert (Brute Force)
- **Concept**: A single right rotation involves taking the last element and moving it to the front. We can simulate this by popping the last element and inserting it at index `0`. We repeat this `k` times.
- **Time Complexity**: $O(K \times N)$. The `pop()` operation is $O(1)$, but inserting at the beginning of a list `insert(0, ...)` takes $O(N)$ time because all other elements must be shifted. Doing this $K$ times makes it highly inefficient and prone to Time Limit Exceeded (TLE) errors for large arrays.
- **Space Complexity**: $O(1)$ as the modification is done in-place.

### 2. Using Slicing (Pythonic / Extra Space)
- **Concept**: We can logically divide the array into two segments: the last `k` elements and the first `n-k` elements. The rotated array is simply the last `k` elements concatenated in front of the first `n-k` elements.
- **Implementation**: Python allows us to elegantly assign this back to the original array using slice assignment: `nums[:] = nums[n-k:] + nums[:n-k]`.
- **Time Complexity**: $O(N)$ because list slicing and concatenation take time proportional to the length of the list.
- **Space Complexity**: $O(N)$ because the slicing operation `nums[n-k:]` and `nums[:n-k]` creates new list objects in memory before the assignment happens. 

### 3. Using Reverse and Two Pointers (Optimal / In-place)
- **Concept**: This is the most optimal algorithm. It achieves linear time without using extra space by relying on array reversals. The process involves three steps:
  1. Reverse the last `k` elements.
  2. Reverse the first `n-k` elements.
  3. Reverse the entire array.
- **Implementation**: We define a helper function `reverse(nums, left, right)` that uses two pointers to swap elements starting from the edges and moving towards the center.
- **Time Complexity**: $O(N)$ because we are iterating over the array segments to reverse them, traversing the array a constant number of times.
- **Space Complexity**: $O(1)$ as the reversing is done entirely in-place using just a few pointer variables.

## Code
```python
class Solution:
    def rotate(self, nums: List[int], k: int) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        # # Using pop and insertion (Brute Force)
        # n = len(nums)
        # rotation = k % n
        # for _ in range(0, rotation):
        #     popped = nums.pop()
        #     nums.insert(0, popped)

        # # Using slicing (Pythonic)
        # n = len(nums)
        # k = k % n
        # nums[:] = nums[n-k:] + nums[:n-k]

        # Using reverse and pointer (Optimal)
        n = len(nums)
        k = k % n        
        def reverse(nums, left, right):
            while left < right:
                nums[left], nums[right] = nums[right], nums[left]
                left += 1
                right -= 1
                
        reverse(nums, n-k, n-1)
        reverse(nums, 0, n-k-1)
        reverse(nums, 0, n-1)    
```
