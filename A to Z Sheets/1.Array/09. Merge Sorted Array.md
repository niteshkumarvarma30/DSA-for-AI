# 88. Merge Sorted Array

**Difficulty:** Easy  
**Topics:** Array, Two Pointers, Sorting

## Problem Description
You are given two integer arrays `nums1` and `nums2`, sorted in non-decreasing order, and two integers `m` and `n`, representing the number of elements in `nums1` and `nums2` respectively.

Merge `nums1` and `nums2` into a single array sorted in non-decreasing order.

The final sorted array should not be returned by the function, but instead be stored inside the array `nums1`. To accommodate this, `nums1` has a length of `m + n`, where the first `m` elements denote the elements that should be merged, and the last `n` elements are set to `0` and should be ignored. `nums2` has a length of `n`.

### Examples

**Example 1:**
- **Input:** `nums1 = [1,2,3,0,0,0]`, `m = 3`, `nums2 = [2,5,6]`, `n = 3`
- **Output:** `[1,2,2,3,5,6]`
- **Explanation:** The arrays we are merging are `[1,2,3]` and `[2,5,6]`. The result of the merge is `[1,2,2,3,5,6]` with the underlined elements coming from `nums1`.

**Example 2:**
- **Input:** `nums1 = [1]`, `m = 1`, `nums2 = []`, `n = 0`
- **Output:** `[1]`
- **Explanation:** The arrays we are merging are `[1]` and `[]`. The result of the merge is `[1]`.

**Example 3:**
- **Input:** `nums1 = [0]`, `m = 0`, `nums2 = [1]`, `n = 1`
- **Output:** `[1]`
- **Explanation:** The arrays we are merging are `[]` and `[1]`. The result of the merge is `[1]`. Note that because `m = 0`, there are no elements in `nums1`. The `0` is only there to ensure the merge result can fit in `nums1`.

### Constraints:
- `nums1.length == m + n`
- `nums2.length == n`
- `0 <= m, n <= 200`
- `1 <= m + n <= 200`
- `-10^9 <= nums1[i], nums2[j] <= 10^9`

---

## Concepts & Explanation: The "Reverse" Two-Pointer Approach

In the previous "Find Union" problem, you used two pointers starting at index 0 and moving forward.

If we try to do that here (starting at the front of `nums1` and `nums2`), we run into a major problem: **Overwriting**. If we find that an element in `nums2` is smaller, and we write it into the front of `nums1`, we will crush the valid data in `nums1` before we even get to read it!

### The Trick: Start from the Back
Notice that `nums1` has a bunch of empty space (`0`s) at the very end. This is a massive hint! If we start comparing the largest numbers and write them at the very end of `nums1`, we will never overwrite any valid data.

We need 3 pointers for this:
- **p1 (Reader 1):** Points to the last valid element in `nums1` (Index `m - 1`).
- **p2 (Reader 2):** Points to the last element in `nums2` (Index `n - 1`).
- **p (Writer):** Points to the absolute very last empty slot in `nums1` (Index `m + n - 1`).

### The Logic
While both `p1` and `p2` have numbers left to read:
1. Compare `nums1[p1]` and `nums2[p2]`.
2. Take the larger of the two numbers and write it at `nums1[p]`.
3. Move the Writer pointer (`p`) back by one step.
4. Move the Reader pointer of whichever array "won" back by one step.

**What happens when one array runs out?**
- **If `p1` runs out first:** This means all the elements originally in `nums1` were moved to the back. We just take whatever is left in `nums2` and plop it into the remaining slots at the front.
- **If `p2` runs out first:** We are completely done! The remaining elements in `nums1` are already exactly where they are supposed to be.

## Step-by-Step: Merging from the Back
Let's walk through exactly what the pointers are doing in **Example 1**.

**The Setup:**
- `nums1 = [1, 2, 3, 0, 0, 0]` (Length is 6. The 0s are empty slots.)
- `nums2 = [2, 5, 6]`
- `m = 3` (Valid numbers in `nums1`)
- `n = 3` (Valid numbers in `nums2`)

Our three pointers start at the very ends:
- **p1 (Reader 1):** Starts at index `2` (value `3`)
- **p2 (Reader 2):** Starts at index `2` (value `6`)
- **p (Writer):** Starts at index `5` (the very last `0`)

**Step 1:**
Compare the values at `p1` and `p2`. Which is larger?
- `nums1[p1]` is 3
- `nums2[p2]` is 6
6 is larger, so the Writer (`p`) writes 6 at the very end.
- `nums1 = [1, 2, 3, 0, 0, 6]`
Move Writer (`p`) left. Move Reader 2 (`p2`) left.

**Step 2:**
Compare the new values.
- `nums1[p1]` is 3
- `nums2[p2]` is 5
5 is larger, so Writer (`p`) writes 5.
- `nums1 = [1, 2, 3, 0, 5, 6]`
Move Writer (`p`) left. Move Reader 2 (`p2`) left.

**Step 3:**
Compare the new values.
- `nums1[p1]` is 3
- `nums2[p2]` is 2
3 is larger, so Writer (`p`) writes 3.
- `nums1 = [1, 2, 3, 3, 5, 6]`
Move Writer (`p`) left. Move Reader 1 (`p1`) left.

**Step 4:**
Compare the new values.
- `nums1[p1]` is 2
- `nums2[p2]` is 2
They are equal! We can pick either, but our code's `else` block automatically grabs the one from `nums2`.
- `nums1 = [1, 2, 2, 3, 5, 6]`
Move Writer (`p`) left. Move Reader 2 (`p2`) left.

**Step 5: The End**
At this point, Reader 2 (`p2`) has dropped below zero. It has run completely out of numbers to read!
Our main while loop finishes. Because `nums2` is empty, any numbers left over in `nums1` (which is just the number `1` sitting at index `0`) are already exactly where they are supposed to be.

**Final Result:** `nums1 = [1, 2, 2, 3, 5, 6]`

## Code
```python
class Solution:
    def merge(self, nums1: list[int], m: int, nums2: list[int], n: int) -> None:
        """
        Do not return anything, modify nums1 in-place instead.
        """
        # p1 points to the last valid number in nums1
        p1 = m - 1
        
        # p2 points to the last number in nums2
        p2 = n - 1
        
        # p points to the very last empty slot in nums1
        p = m + n - 1
        
        # While there are still numbers to compare in BOTH arrays
        while p1 >= 0 and p2 >= 0:
            
            # If the number in nums1 is larger, put it at the end
            if nums1[p1] > nums2[p2]:
                nums1[p] = nums1[p1]
                p1 -= 1
            
            # Otherwise, the number in nums2 is larger (or equal), put it at the end
            else:
                nums1[p] = nums2[p2]
                p2 -= 1
                
            # Regardless of which one we picked, our writer pointer moves back one step
            p -= 1
            
        # If nums2 still has elements left over, it means they are the smallest 
        # numbers overall and belong at the very front of nums1.
        while p2 >= 0:
            nums1[p] = nums2[p2]
            p2 -= 1
            p -= 1
            
        # Notice we don't need a "while p1 >= 0:" loop! 
        # If nums1 has elements left over, they are already sitting in the correct 
        # positions at the front of nums1, so we do nothing!
```
